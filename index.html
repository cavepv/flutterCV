Introduction to Flutter

Flutter is Google's modern, open-source UI toolkit for building beautiful, natively compiled applications for mobile, web, desktop, and embedded devices from a single codebase.

Why Choose Flutter?

  • Cross-Platform Development: Write once, run on Android, iOS, Windows, macOS, Linux, and web
  • Fast Development: Hot reload for instant feedback on code changes
  • Expressive & Flexible UI: Customizable widgets for any platform
  • Native Performance: Compiled to native ARM code with no bridging overhead
  • Single Codebase: Reduce development time and maintenance costs
💡 Did You Know?
Flutter apps are compiled to native ARM code using the Dart VM, not web technologies like JavaScript. This gives them excellent performance across all platforms.

The Four Layers

1. Embedder

Platform-specific code that handles rendering surface, threading, and platform integrations.

2. Engine

C++ code that provides high-performance rendering using Skia graphics library.

3. Framework

Dart UI framework with widgets, rendering, gestures, and animation.

4. Apps

Your Dart code implementing the Flutter app logic and UI.

State Management

State management is how you handle data that changes over time in your app. Flutter provides several approaches, from simple to complex.

Understanding State

Ephemeral State: State that can be managed locally within a widget (using setState).

App State: User data or app-wide state that needs to be shared across multiple widgets.

My Todo List:

class MyHomePage extends StatefulWidget {
  @override
  _MyHomePageState createState() => _MyHomePageState();
}

class _MyHomePageState extends State<MyHomePage> {
  int counter = 0;
  List todos = [];

  void _incrementCounter() {
    setState(() {
      counter++;
      todos.add('Todo item ${counter}');
    });
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Local State')),
      body: Center(
        child: Column(
          mainAxisAlignment: MainAxisAlignment.center,
          children: [
            Text('You have ${counter} todos:'),
            ...todos.map((todo) => Text(todo)).toList(),
          ],
        ),
      ),
      floatingActionButton:
        FloatingActionButton(onPressed: _incrementCounter),
    );
  }
}

Simple State Management with Provider

import 'package:flutter/material.dart';
import 'package:provider/provider.dart';

class Counter extends ChangeNotifier {
  int _count = 0;
  
  int get count => _count;
  
  void increment() {
    _count++;
    notifyListeners();
  }
}

class MyApp extends  StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return ChangeNotifierProvider(
      create: (_) => Counter(),
      child: MaterialApp(
        home: MyHomePage(),
      ),
    );
  }
}

Platform Channels: Dart ↔ Native Communication

Use platform channels to communicate between Flutter and native code:

import 'package:flutter/services.dart';

class PlatformServices {
  static final PlatformChannel _channel = MethodChannel('com.example.app/platform');

  Future<String?> getPlatformVersion() async {
    try {
      final version = await _channel.invokeMethod('getPlatformVersion');
      return version;
    } catch (e) {
      return null;
    }
  }

  Future<void> showToast(String message) async {
    await _channel.invokeMethod('showToast', {'message': message});
  }
}

Android (Kotlin) 
import io.flutter.embedding.engine.platform.PlatformMessageHandler

class FlutterActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        GeneratedPluginRegistrant.registerBuffer(this)
        
        PlatformChannel.setPlatformMessageHandler { message, response ->
            when (message) {
                'showToast' -> {
                    Toast.makeText(this, response.getString('message'), Toast.LENGTH_SHORT).show()
                }
            }
        }
    }
}
iOS (Swift) 
import Flutter

@objc(FlutterPlugin)
class MyPlugin: NSObject, FlutterPlugin {
    func handle(method: String, arguments: [String: Any]?, response: FlutterResult) {
        switch method {
        case 'showToast':
            guard let message = arguments?['message'] as? String else { return }
            showToast(message: message)
        default:
            break
        }
    }

    func showToast(message: String) {
        let alert = UIAlertController(title: , message: message, preferredStyle: .alert)
        alert.addAction(UIAlertAction(title: "OK", style: .default))
        UIApplication.shared.window?.rootViewController?.present(alert, animated: true)
    }
}

Navigation & Routing

Flutter provides powerful navigation tools to handle routing between different screens in your app.

Basic Navigation with Navigator

class FirstScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('First Screen')),
      body: Center(
        child: ElevatedButton(
          onPressed: () {
            Navigator.push(
              context,
              MaterialPageRoute(builder: (_) => SecondScreen()),
            );
          },
          child: Text('Go to Second Screen'),
        ),
      ),
    );
  }
}

class SecondScreen extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: Text('Second Screen')),
      body: Center(
        child: ElevatedButton(
          onPressed: () => Navigator.pop(context),
          child: Text('Go Back'),
        ),
      ),
    );
  }
}

Named Routes

Use named routes for better organization in larger apps:

class AppRoutes {
  static final String firstScreen = '/';
  static final String secondScreen = '/second';
  static final String detailsScreen = '/details';
}

class MyApp extends StatelessWidget {
  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      initialRoute: AppRoutes.firstScreen,
      routes: {
        AppRoutes.firstScreen: (_) => FirstScreen(),
        AppRoutes.secondScreen: (_) => SecondScreen(),
        AppRoutes.detailsScreen: (_) => DetailsScreen(),
      },
    );
  }
}

💡 Pro Tips
  • Responsive Design: Use media queries and LayoutBuilder for adaptive layouts across different screen sizes
